# Learn Any Topic

## Core Outcome

Create a tutorial that lets the target learner study the topic with minimal extra searching. Connect background, concepts, methods, examples, terminology, practice, and review criteria into one coherent learning path.

## Workflow

### 1. Confirm Tutorial Language

Determine which language the tutorial should be written in. If clear from context, proceed; if ambiguous, ask. Do not default to English because this skill is written in English.

### 2. Frame the Learning Job

Identify the topic, target learner, desired depth, output format, and acceptance criteria. Ask only for missing information that would materially change the result.

Convert the request into a concrete learning objective: what to understand, what to do, key terminology, useful examples/exercises, expected artifact.

### 3. Build the Source Map

Prefer primary and recognized sources over generic summaries. Use this source ladder:

1. Standards, official documentation, laws, specifications
2. Textbooks, peer-reviewed papers, university material
3. Respected field guides, design systems, industry handbooks
4. Influential practitioner writing, case studies, widely cited essays
5. Community material only as supporting context

If the field has competing schools of thought, name the disagreement and explain the practical consequence.

When the topic involves time-sensitive material (laws, APIs, prices, active research), verify current sources. If browsing is unavailable, state which claims may need live verification.

### 4. Design the Knowledge Map

Before drafting, structure: prerequisites, root background, core concepts, key terms, standard workflows, examples (simple → realistic), common mistakes, practice tasks, review checklist.

Use this tutorial shape: title/promise → orientation → prerequisites → vocabulary → mental model → main concepts → standard workflow → worked example → common mistakes → practice path → review checklist → source list.

### 5. Write the Tutorial

Write in the confirmed language. Prefer continuous explanation over disconnected bullet lists.

- Define what a thing is before what it is not.
- Replace broad claims with specific mechanisms.
- Explain terms when they first appear.
- Move from root causes to principles, then to procedures and examples.
- Use diagrams, tables, or checklists when they reduce confusion.
- Keep citations close to factual claims without overloading.

### 6. Generate the Artifact

For document outputs, include: title, orientation, sections, glossary, practice/review section, source list.

### 7. Review, Find Gaps, Revise

Run at least one review loop: coverage, source quality, learner fit, terminology, coherence, practice, artifact integrity (no placeholders, broken references, missing files).

## Output Contract

Report: delivered file location, source backbone used, review checks completed, any known limitations.
