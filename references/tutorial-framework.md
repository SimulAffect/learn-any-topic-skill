# Tutorial Framework

Use this reference when building a substantial self-study tutorial or course-like explanation.

## Minimum Useful Shape

1. Title and promise
   State what the learner will understand or be able to do.

2. Orientation
   Explain why the topic exists, what problem it solves, and where it is used.

3. Prerequisites
   Name assumed knowledge. If the learner may lack it, add a short bridge.

4. Core vocabulary
   Define key terms in plain language before relying on them.

5. Mental model
   Give the learner a compact way to reason about the topic.

6. Main concepts
   Move from foundational concepts to applied patterns. Each concept should answer "what it is", "why it matters", and "how to recognize or use it".

7. Standard workflow
   Show the normal process an experienced person follows. For technical topics, include setup, inputs, outputs, decisions, and failure handling. For conceptual topics, include analysis steps and judgment criteria.

8. Worked example
   Start with a small example, then extend it toward a realistic case.

9. Common mistakes
   Explain why each mistake happens and how to detect it.

10. Practice path
   Add exercises, prompts, mini-projects, or self-check questions.

11. Review checklist
   Give criteria the learner can use to judge their own understanding.

12. Source list
   Include enough source context for the user to verify or go deeper.

## Chapter Recipe

For each major section, use this pattern:

- Start with a concrete situation or question.
- Define the central idea.
- Explain the mechanism or reason.
- Give one simple example.
- Give one realistic example or edge case.
- State how the learner should apply it.
- Connect it to the next section.

## Depth Controls

For beginners, emphasize vocabulary, intuitive examples, and mistakes. For intermediate learners, emphasize workflows, tradeoffs, and implementation details. For advanced learners, emphasize edge cases, competing models, source disputes, and evaluation standards.

## Learning Artifacts

Choose artifacts based on the topic:

- glossary for terminology-heavy fields
- roadmap for broad domains
- decision tree for judgment-heavy tasks
- checklist for repeatable work
- worked examples for procedural skills
- source map for research-heavy topics
- exercises for skill acquisition

Avoid adding artifacts only to look comprehensive. Every artifact should help the learner do something.
